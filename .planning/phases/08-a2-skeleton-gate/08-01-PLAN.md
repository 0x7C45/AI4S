# Plan 01-01: A2 骨架门禁 — RTL 解析 + cocotb/Verilator testbench 生成

## Objective

构建 A2 验证环境自动生成的骨架门禁流水线：`run.py` 五参数入口 → `rtl_parser` 解析 RTL 接口 → `skeleton_gen` 生成 cocotb+Verilator testbench → `sim_runner` 在 Docker 容器内仿真。case1 作为门禁验收标杆：能编译、能跑、DUT 端口连对、有驱动/监视/scoreboard/反压。

Purpose: 建立完整骨架管道，使 Phase 9 能聚焦覆盖率采集，Phase 10 聚焦通用化。
Output: 可运行的 run.py + src/ 三模块 + templates/ 模板 + case1 门禁通过。

## Context

- A2 验证环境自动生成，cocotb + Verilator 5.050 路线（LOCKED）
- 代码在 E 盘 E:/AI4S/Track-A/A2-verification/，工作分支 exec/win-zcode
- 环境：Docker linux/amd64 + verilator/verilator:v5.050（烟雾测试已验证）
- case1 公开样例在 testcases/A2_public_dataset/case1/（只读参考）
- case1 真实模块 axi_adapter_rd，wrapper case1_cocotb_top（硬编码 ADDR=16/S=32/M=16）
- 烟雾测试已确认：需 -Wno-fatal、cocotb 2.0 API（unit=）、Makefile SIM=verilator、镜像无 pip

### Locked Decisions (from CONTEXT.md)

- **D-01**: 入口 run.py，五参数 --rtl --top --out --seed --num-seq
- **D-02**: Phase 8 只实现 rtl_parser + skeleton_gen + sim_runner + run.py 骨架
- **D-03**: COMPILE_ARGS 必须含 -Wno-fatal（Verilator lint 致命，烟雾测试确认）
- **D-04**: 生成的 testbench 适配 cocotb 2.0 API（Clock unit= 非 units=）
- **D-05**: Makefile 默认 SIM=verilator
- **D-06**: 镜像无 pip，sim_runner 的 Docker 调用含 apt-get install python3-pip bootstrap
- **D-07**: top_module 陷阱——rtl_parser 解析真实模块名，不盲信 design.json
- **D-08**: AXI 驱动用 cocotbext-axi（AxiMasterRead/AxiRamRead/AxiReadBus.from_prefix）
- **D-09**: 产物输出到 --out，不写 testcases（locked）
- **D-10**: 协议推断三类：AXI（s_axi/m_axi 前缀）、SRAM-like、valid/ready stream

<action>
创建 src/rtl_parser.py，实现 `parse(rtl_dir, top_hint=None) -> DesignInfo`（per D-07, D-10）：
- 扫描 rtl_dir 下所有 .v 文件
- 解析每个文件的 module 定义：模块名、参数（parameter/localparam）、端口（input/output/inout + 宽度 + 名称）
- 识别真实顶层模块：若 top_hint 与某个 module 名匹配则用它；否则取无被例化记录的顶层 module（per D-07，不盲信 design.json 的 caseN 别名）

  - valid/ready stream：端口名含 valid/ready 后缀对
- 返回 DesignInfo dataclass：top_module, files, parameters, ports（含 direction/width/protocol_group）, clock, reset, inferred_protocols
