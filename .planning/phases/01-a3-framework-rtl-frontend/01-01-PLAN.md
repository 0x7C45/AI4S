# Plan 01-01: A3 Synthesis Framework + RTL Frontend

## Objective

Build a working end-to-end RTL logic synthesis pipeline: Makefile + Python scripts that generate Yosys .ys scripts (per D-01), apply a unified synthesis flow with variable ABC sequences (per D-02), use Yosys read_sdc for constraints (per D-03), parse problem.yaml for metadata (per D-04), optionally verify via Icarus Verilog simulation (per D-05), and auto-fallback to $default on failure (per D-06). Validate with LSV01 (simplest public circuit).

Purpose: Establish the complete synthesis pipeline so Phase 2 can focus on correctness across all 10 circuits, and Phase 3 on PPA optimization.
Output: Working Makefile, synth.py, config.py, verify.py, config.json, submission.yaml -- full working tool that synthesizes LSV01 end-to-end.

## Context

- Building A3 tool for hackathon Track A (EDA Software), 61-hour deadline
- Open-source-based: Yosys 0.54 with Berkeley ABC for synthesis
- 10 public circuits LSV01-LSV10 in `Track-A/A3-synthesis/testcases/public/`
- Submission template at `Track-A/A3-synthesis/testcases/submission_template/`
- Nangate45 Liberty at `Track-A/A3-synthesis/testcases/lib/nangate45/NangateOpenCellLibrary_typical.lib`
- Reference Yosys script at `Track-A/A3-synthesis/testcases/scripts/run_yosys.py`
- LSV01 (epfl_priority): combinational, top module name is `top`, 1102 lines, no clock/reset

### Locked Decisions (from CONTEXT.md)

- **D-01**: CLI script mode -- Python generates .ys script, calls `yosys -q -s script.ys`
- **D-02**: Unified flow + variable ABC -- all circuits use same Yosys flow, only ABC sequence varies
- **D-03**: Yosys `read_sdc` -- native SDC reading
- **D-04**: Python parses problem.yaml -- extract top_module, clock, reset
- **D-05**: Built-in Icarus Verilog simulation verification -- post-synthesis self-check, graceful degradation if iverilog unavailable
- **D-06**: Auto-fallback -- point failure retries with $default config

### Key Research Pitfalls (from A3_STRATEGY.md)

- **Pitfall #1**: ABC script MUST include `map` at the end -- without it, output is NOT a mapped netlist
- **Pitfall #2**: `dfflibmap` MUST come after `abc` -- ABC only maps combinational logic, FFs need separate mapping
- **Pitfall #5**: `flatten` can break sequential circuits -- use carefully; `synth -flatten` is acceptable for most cases but test without `-flatten` for complex sequential designs
- **Pitfall #4**: Use `setundef -zero` to resolve X values before output

### Reference Flow (from run_yosys.py)

The competition's own reference script uses:
```
read_verilog -sv {rtl}
hierarchy -check -top {top}
synth -top {top} -flatten -noabc
dfflibmap -liberty {liberty}
abc -liberty {liberty} -script "{abc_script}"
clean
stat -liberty {liberty}
setundef -zero
splitnets -driver
clean
write_verilog -noattr -noexpr {netlist}
```

ABC scripts use `+strash;` prefix notation where `+` means "append to built-in script".
Reference ABC mappings: `&get -n; &dch -f; &nf -D 10000; &put`

### Makefile Interface (from template)

The template Makefile passes `--output $(OUT_DIR)/netlist.v` (not `--out-dir`). The tool must accept `--output` pointing to the full netlist.v path.

**CLI Interface:**
```

```

`--output` is the full path to netlist.v (matching Makefile template). If `--top` is not provided, look for `problem.yaml` in the parent directory of `--rtl` and parse it for `top` field.

**Core flow (per D-01, D-02):**

1. Parse args. If `--top` missing, call `parse_problem_yaml()` from config.py (per D-04)
2. Load config via `load_config(config_path, circuit_id)` from config.py
3. Get point config: `point_configs[point_number - 1]` (POINT is 1-indexed)
4. Extract abc_script via `extract_abc_script(point_config)`
5. Validate abc_script ends with a mapping command: search for `map`, `amap`, `&nf`, `&put` at end of script. If not found, append `; map` and log a warning. This prevents Pitfall #1.
6. Generate Yosys .ys script file at `{output_dir}/_synth.ys`

**Generated .ys script content (per D-02, unified flow):**

```yosys
# Read technology library
read_liberty -lib {liberty}

# Read RTL design
read_verilog -sv {rtl}

# Hierarchy processing
hierarchy -check -top {top}

# Unified synthesis flow (no ABC, no dfflibmap -- we do those separately)
synth -top {top} -flatten -noabc

# Map flip-flops BEFORE abc (research pitfall #2)
dfflibmap -liberty {liberty}

# ABC optimization + technology mapping
abc -liberty {liberty} -script "{abc_script}"

# Cleanup
clean

# Print statistics
stat -liberty {liberty}

# Resolve undefined values (research pitfall #4)
setundef -zero

# Split multi-bit nets for cleaner output
splitnets -driver

# Final cleanup
clean

# Write gate-level netlist
write_verilog -noattr -noexpr {output}
```

This matches the reference `run_yosys.py` flow. The key ordering is: synth -noabc -> dfflibmap -> abc (with mapping at end of script) -> clean -> setundef -> write.

**SDC handling (per D-03):**
For the abc command, pass SDC constraints via the `-constr` flag:
```
abc -liberty {liberty} -constr {sdc} -script "{abc_script}"
```
This uses Yosys native SDC support. The `-constr` flag to `abc` passes timing constraints for timing-aware mapping.
