<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Filelist module set to global registry | Module names and instance edges determine the executable design graph. |
| Parent/child port connections to flattened signals | Direction, width, and hierarchy mapping determine data movement across scopes. |
| Variable memory indices to runtime storage | RTL expressions select runtime elements and must be bounds checked. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|----------|----------|-----------|----------|-------------|-----------------|
| T-06-07 | Tampering | global module registry and duplicate definitions | high | mitigate | Detect duplicate module names, retain source locations, and fail compilation before elaboration. |
| T-06-08 | Elevation of Privilege | port direction/binding logic | high | mitigate | Bind only declared directions, validate connection count/name/width, and isolate child scopes with deterministic prefixes. |
| T-06-09 | Denial of Service | recursive/cyclic module instantiation | medium | mitigate | Track active elaboration stack and reject cycles or unbounded instance depth with a source-linked diagnostic. |
| T-06-10 | Tampering | variable-index memory writes | medium | mitigate | Validate index bounds and element widths before read/write; report out-of-range accesses explicitly. |
</threat_model>
